## 目的

「北但馬地震」のような **災害という出来事そのものの Wikipedia 記事** を候補から落とす。行けない出来事を「宿のまわりの見どころ」に並べるのは明確な誤り。既存の除外軸(廃止施設・他社の宿・人物・合戦・一般名詞・動物の種名・広域公園・索引記事)のうち「合戦」は出来事だが、災害は対象外で素通りしている。

### 検証済みの判定式

`DEFINITION_DISASTER = /で発生した(地震|大地震|噴火|火災|水害|洪水)である/` を **definitionPredicate(definitionScope('', extract))** に当てた結果、250記事中 **ヒット1件(北但馬地震のみ)・誤爆0件**。語の単純列挙ではなく「〜で発生した〇〇である」という**定義文の構造一致**なので、「〜のふもとにある記念碑である」のような記事には当たらない。作業役はこの数値を鵜呑みにせず**自分で再実測して NIGHTLOG に書くこと**。

## 実装上の罠

1. **保護リストより前に置く**。後ろだと届かない可能性がある(R141・R142 の実例)。
2. **`definitionPredicate` を必ず通す**。生の extract に当てると主題部の記事名を見ることになり「名前で落とす」のと同じになる(R117 の教訓、engine.js 872-881行のコメント参照)。
3. **kinosaki の順位は必ず動く**。27位が消えるので28位以降が1つずつ繰り上がり、more の先頭1件が30位に入る。これは想定内。他4エリアは `dump-rank` **完全無差分**であること。
4. `北但大震災伝承銅像`(kinosaki 24位)と `水害碑`(beppu 21位)が**残っている**ことを、テキストでも撮影でも必ず確認する。この2件が消えたら実装が間違っている。

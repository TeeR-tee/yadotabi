## 実装方針(本命: 矩形として扱う)
1. `nudgeOverlaps` の第2引数を「点の配列」から **`obstacles`(矩形の配列)** に一般化する。
   矩形は地図コンテナ座標で `{left, top, right, bottom}`。宿ピンも
   中心 ± 15px の 30x30 矩形として同じ配列に入れ、**点と円の混在をやめる**。
2. 判定を**矩形 vs 矩形の重なり**に置き換える。ピンは中心 `p` と自分の実寸
   (番号ピン 24、上位ピン 27、宿ピン 30)から矩形を作る。
   「余裕」は円の距離差ではなく**矩形間の最小距離**(軸ごとの隙間の hypot)で測る。
   `clearance` は `min(矩形間距離 - PAD)` とし、`PAD` は 4px 程度の見た目の余白から決めて定数化する。
   **ピン同士の距離定数(TOP_DIST / SUB_DIST / HOTEL_DIST)の値は変えない**
   (ピン同士の分離は現状維持。今回直すのは障害物との関係だけ)。
3. **帰属表示だけは絶対制約**にする。ベストエフォートの「いちばんマシ」フォールバック
   (`app.js:1256-1260`)に到達した場合でも、**帰属表示の矩形と重なる候補は採用しない**。
   リング探索を使い切っても見つからないときは、箱の下端 + ピン半径 + PAD の位置へ
   最終退避させる(必ず解がある決定的な逃がし先を1つ用意する)。
   `clamp` の後にも同じ制約を通し、縁に張り付いた結果として箱に乗ることを防ぐ。
4. 箱の矩形は `getBoundingClientRect()` から毎回実測する(1行/2行のどちらでも自動追従)。

## 代替案(本命が複雑になりすぎる場合。作業役が実測で選んでよい)
- **案B: 地図下部ではなく「帰属表示の帯」をピン禁止帯にする**。
  帰属表示は `topright` なので、実際には**地図上端の高さ `aRect.height + PAD` の帯のうち
  箱の水平範囲**をピン配置禁止にし、`clamp` の上限 y をその帯の下端に引き上げる。
  実装は `clamp` の数行で済み、順位に依存しない。
  副作用は「地図の上端右寄りにピンが来なくなる」こと。実測で 139.8x14 の箱に対し
  影響を受けるのは上端 18px 程度の帯のみなので、撮影で確認して許容できるか判断する。
- **案C: 帰属表示を `bottomright` に戻したうえで案B(下端の帯)を適用**。
  R31 のコメント(`app.js:1194`)は「右下は番号ピンが密集しやすい」としているが、
  帯で禁止するなら密集度は関係ない。撮影で見た目を比べて良ければ採ってよい。
- **どの案でも、帰属表示の DOM・CSS(display / visibility / opacity / 文言)は一切変更しない。**

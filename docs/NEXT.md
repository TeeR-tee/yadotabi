## 目的
Wikipedia 要約(extract)の **2文目以降**の語に反応してカテゴリが誤判定される。
画面に出ている実害は hakone 18位「長興山のシダレザクラ」が **神社・寺院** と表示される1件
(2文目「紹太寺の敷地内」の `寺` に反応)。R115・R119・R145・R141 で既に使われている
「定義文(1文目)だけを見る」方式(`definitionScope()`)に揃え、判定の根拠を統一する。

## 順位が動く可能性(事前見積もり)
`rank()` の CATEGORY_PENALTY は **`category === 'other'` を減点対象から除外**している
(`assets/engine.js` の該当ブロック)。よって 8件が `other`(スポット)に移ると、
**その記事が属していたカテゴリの枠が1つ空き、同カテゴリの後続記事の減点が1段階軽くなる**。
- 影響が出うるのは 8件のいずれかが top30(または far)に入っているエリア: **hakone / kusatsu / beppu / kinosaki**。
- 特に kinosaki は `park` が4件中3件(竹野浜・竹野海岸・はさかり岩)抜けるため、
  残る公園カテゴリの記事の順位が上がる可能性が高い。R146 で「竹野鉱山」が同じ理由で 31位→18位 に動いた前例がある。

- 動いた順位は「どのカテゴリの枠が空いて誰が何位上がったか」の形で NIGHTLOG に説明できること。

## 実装方針
`guessWikiCategory()` の第2ループの走査対象を `e` から、既に同関数の先頭で計算済みの
`scope`(= `definitionScope(t, e)`)に差し替える。**それだけ**。
- `scope` はタイトルを含むが、第1ループ(タイトル部分一致)を通過した後なので **新たにヒットは増えない**
  (実測で確認済み。22件の結果表がその証拠)。
- `isDenied(hint, scope)` は既に `scope` を見ているので変更不要。
- コメントに「なぜ2文目を見ないか」と R115/R145 と同じ方式である旨を書くこと。

## 却下した案とその理由
- **「主語に当たる部分だけを見る」(`definitionPredicate()` を噛ませる)**: 述部だけにすると
  「〜は…にある**寺院**である」のような正当なケースは残るが、実測の8件は全て2文目が原因であり、
  述部化しても同じ結果になる一方、主題部を落とすことで「〇〇神社(記事名)は…」型の取りこぼしが増える
  リスクだけが乗る。R117 は「名前で落とす」除外判定のための道具で、カテゴリ**推定**とは目的が違う。**採らない**。
- **「2文目以降を見るが重みを下げる」**: 現状のコードに重み概念が無く、rank 側に手を入れる必要がある。
  変更禁止範囲(rank の重み)に触れるため **不可**。
- **「長興山のシダレザクラ 1件だけ個別対処」**: R146 の castle と同じ「裸の語が地名に当たる」問題で、
  8件すべてが同じ構造の誤判定。個別対処は同じ罠を8回踏むだけなので採らない。
- **見送り案(何もしない)**: 実測の結果 **悪化0件・改善8件**で、うち4件(kinosaki の海岸3件+駅)は
  「公園」という明確な嘘のラベルが消える。割に合うので **実施を推奨する**。

## 実装上の罠
1. **`scope` は120字で頭打ち**。「京都大学…地球熱学研究施設」のように記事名が長いと1文目全体が入らない。
   これは意図どおり(定義文の冒頭しか見ない)で、結果も正しくなるので直そうとしないこと。
2. **第1ループは触らない**。castle の末尾一致(R146)を巻き込むと 26→4件 の成果が壊れる。
3. `definitionScope()` の引数順は `(title, extract)`。既に `var scope = definitionScope(t, e);` が
   関数先頭にあるので **新しく計算し直さない**(二重計算はバグの温床)。
4. **順位変化を「実装ミス」と混同しない**。CATEGORY_PENALTY の枠が空くことによる繰り上がりは
   構造上不可避の正しい副作用。ただし dogo が動いたら実装ミス。
5. 上の22件・8件という数値は計画役の実測だが、**作業役は自分で数え直して自分の数値を書くこと**。
   食い違ったら自分の実測を採用し、その旨を NIGHTLOG に書く。

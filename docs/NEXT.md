## 実装方針

`engine.js:244 DEFINITION_LODGING_NG` の直後に定数を2本置く:

```
var DEFINITION_GONE_MARK = 'かつて';
var DEFINITION_GONE_PAST = ['存在した', '存在していた', 'あった'];
```

`isExcludedArticle()` の R117 のループ(`engine.js:479-482`)の**直後**に、同じ `predicate` を使って
「`predicate` に `かつて` が含まれ、**かつ** `DEFINITION_GONE_PAST` のいずれかが含まれる」なら `return true` を足す。
`predicate` は既に計算済みなので、再計算しないこと。

**「かつて」を必須にする理由(緩めてはいけない)**: 「あった」単独にすると
`湯築城`「愛媛県松山市道後公園に**あった**日本の城。」(dogo **1位級の正当な観光対象**・実際は4位)、
`石垣山城`・`羽根尾城`・`長野原城`・`道後村`・`道後湯之町` を巻き込む。
城跡・一夜城歴史公園は「跡地を整備した公園」として**現地に行ける**ので落としてはいけない。
実測でこれらは全て「かつて」を含まないため、2語の AND で誤爆0になっている。

**「に存在した」単独も足さないこと**: `群馬鉄山`(kusatsu 15位)が該当するが、
「かつて」を含まないため今回の対象外とする。鉱山跡は現地に遺構が残る場合があり、
1件のために条件を広げると判定の根拠が崩れる。R116 と同じく別タスクに回してよい。

**救済経路は既存のまま**: `engine.js:917-918` の `hasOsmTagEvidence()` による救済は今回も効くので、
OSM に観光タグ付きで実在する要素と一致する記事は落ちない(= 現地に何かが残っていれば残る)。ここは触らない。

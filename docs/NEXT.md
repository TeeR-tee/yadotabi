## 実測で判明した前提(計画役が 5エリアの fixture 全 250 記事で実測済み)
対象コード: `assets/engine.js:481`
```
{ category: 'castle', label: '城・城跡', words: ['城跡', '城址', '城'] },
```

`guessWikiCategory()`(`assets/engine.js:907`)は **(1)タイトル部分一致 → (2)extract 部分一致** の2周で、`castle` 行が `park`/`museum`/`place_of_worship` より**前**にあるため、裸の `城` が最初に当たって全部を castle にしている。

## 実装方針(計画役の推奨・作業役は実測で裏を取ってから採用すること)
`assets/engine.js` の `castle` 判定だけを「**タイトル末尾一致**」に変える。
1. `WIKI_CATEGORY_HINTS` の castle 行の `words` を `['城跡', '城址']` に減らす(裸の `城` を削る)。
2. `guessWikiCategory()` に castle 専用の末尾判定を足す。タイトルから曖昧さ回避の括弧(`港村 (兵庫県)` 形式)を落としてから `/(城|城跡|城址)$/` を当て、当たれば castle を返す。既存の `stripDisambiguation()` が engine.js 内にあるので**新規に正規表現を書かず既存関数を再利用する**こと(`grep -n "function stripDisambiguation" assets/engine.js` で確認)。
3. 末尾判定は `words` ループ(タイトル部分一致の周)と**同じ優先順位の位置**で評価する。順番を変えると別カテゴリの結果が動く。

計画役の実測では、この方式で **castle の変化は 26件 → 4件(誤爆0・本物4件は全て castle のまま)**。

## 却下した案とその理由
- **案X: castle 行を `park`/`museum` より後ろに移す** — 順序を変えると castle 以外の記事のカテゴリまで連鎖的に変わる。実測で `玄武洞駅` が park に化ける等、狙っていない差分が出る。カテゴリは `CATEGORY_PENALTY`(`engine.js:504`)で**順位に効く**ため、順位が動く=不採用条件に直撃する。
- **案Y: 除外リスト(isExcludedArticle)で落とす** — R146 は「候補として妥当だがラベルだけ誤り」。落としたら順位が動くので明確に禁止。
- **案Z: `城崎` `城下町` などの否認語(deny)を castle 行に足す** — kinosaki の19件は `城崎` 以外にも `城崎郡`(竹野町・中竹野村ほか)経由で当たっており、語の列挙では取りこぼす。構造(末尾一致)で解くほうが 5エリアで誤爆0を証明しやすい。R115 の deny は hot_spring 専用で「他のカテゴリ行には付けない」と `engine.js:474` に明記されている方針にも反する。

## 実装上の罠(直近サイクルは毎回別の罠に当たっている)
1. **`extract` 周(2周目)も同じ castle 行を使う**。`words` から `城` を消すと extract 経由の castle も消える。実測ではそれが正しい(`南町停留場`「伊予鉄道城南線」、`愛媛大学ミュージアム`「城北キャンパス」はどちらも誤り)が、**extract 周では末尾判定を当てないこと**(extract 末尾に `城` が来るのはただの偶然)。
2. **`城崎麦わら細工伝承館` が castle → `hot_spring` に化ける**(計画役の実測で確認)。理由は extract に「城崎温泉郷」があり `温泉` 行が当たるため。これは R146 の修正で新たに生まれる**別の誤ラベル**で、ROADMAP には未起票。**今回は直さない**が、撮影で気づいたら NIGHTLOG の「次」に一言残すか ROADMAP に新規起票すること(同サイクルで直そうとしないこと。museum の words に `伝承館`/`文芸館` を足す話になり、範囲が広がって順位検証が壊れる)。
3. **`石垣山一夜城歴史公園` は castle → `park` になる**。これは正しい(跡地を整備した公園)が、hakone の `dump-rank` でカテゴリ列が動く。**順位が変わっていなければ合格**。カテゴリが動くと `CATEGORY_PENALTY` の累積が変わって順位も動きうるので、hakone と dogo と kinosaki は順位列を1行ずつ突き合わせること。
4. **R141/R142 の「保護リストより前か後ろか」の罠は今回は無関係**。R146 は `isExcludedArticle` に一切触らない。触ったら不採用。
5. OSM 由来の候補は `geo.js` の `detectCategory` が別経路でカテゴリを付けている。**`geo.js` は変更禁止**。今回の変更は wiki 由来(`fromWikiArticle`)だけに効く。

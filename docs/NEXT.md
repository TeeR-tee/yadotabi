## 目的

草津の **22位「ドクターフィッシュ」**(カテゴリ「動物園」・宿から656m・要約×写真×公式×・source=osm)は、
2位に既に居る **「草津熱帯圏」の中の展示**であって、宿を出て向かう独立した行き先ではない。

## 実装方針

**`isExcludedName()` には入れない。** 理由は「実装上の罠」節に書いたとおり、この関数は**名前しか受け取らない**。

置き場所は `assets/engine.js:1237` の **R127 フィルタ(統合・昇格の後)とまったく同じ形**で、その直前か直後に
1ブロック足す。条件は4つ全部が揃ったときだけ `false`(落とす):

1. `item.source === 'osm'`(統合で `both` に昇格していない単独候補)
2. `item.category === 'zoo' || item.category === 'aquarium'`(**タグ由来。geo.js が既に `detectCategory` で付けている。geo.js は触らない**)
3. `!item.summary && !item.wikipediaTitle && !item.wikidataId && !item.website`(記事の裏付けも公式サイトも無い)
4. 名前が**施設語を1つも含まない**(新定数 `ZOO_FACILITY_WORD` を用意。最低限 `園`・`館`・`小屋`・`パーク`・`ランド`・`ZOO`・`Aquarium`・`サファリ`・`牧場`・`里`・`村`・`広場`・`舎` を含めること。**作業役が4エリアで実測して過不足を確認し、実測値を採用してよい**)

`fromOsmSpot()`(engine.js:821)は `category`・`website`・`wikipediaTitle`・`wikidataId` を既に item に載せているので、
**engine.js の1ファイル・1ブロックだけで済む**(`spot.tags` を新たに運ぶ必要は無い)。

## 却下した案とその理由

- **(a) `tourism=zoo` のタグだけで落とす** → 実測で正当な動物園6件(ワンダーラクテンチ動物園・山地獄動物園・だっこしてZOO ほか)を巻き込む。**却下**。
- **(b) 動物の種名リストを `GENERIC_NAME_NG` に完全一致で足す(R142 方式)** → `カピバラ`・`ウサギ` を名前だけで落とすと、**将来どのエリアでも**「ウサギ島」のような固有名や、動物名を冠した正当な施設を機械的に危険にする。`ラマ、ヤギ、ヒツジ`・`ふわふわ` のような列挙名・愛称は有限のリストで書き切れず、そもそも網羅不能。**却下**(カテゴリという構造情報が使えるのに名前の列挙に頼る理由が無い)。
- **(c) 距離や親施設との近接で落とす(草津熱帯圏から100m以内の zoo は展示とみなす)** → rank の閾値に近い新しい数値を持ち込むことになり、変更禁止範囲に触れる。またエリアごとに施設の広さが違う。**却下**。
- **(d) `isExcludedName` に入れる** → 名前しか渡らないので条件2が書けない。**構造的に不可能**(下記)。

## 実装上の罠(直近2サイクルと**種類が違う**ので読み違えないこと)

R141・R142 はどちらも「`NAME_PROTECT_SUFFIX` による保護が先に効いて判定に届かない」罠だった。
**R143 でこの罠は起きない**。計画役が対象8件を `isProtectedName()` に当てて実測した結果、
`カピバラ`・`ニホンザル`・`ラマ、ヤギ、ヒツジ`・`ウサギ`・`ハクビシン`・`ドクターフィッシュ`・`爬虫類`・`ふわふわ`
の**8件すべてが protected=false**(保護語で終わらない)。順序の罠は無い。

**代わりに R143 固有の罠が2つある**:

1. **`isExcludedName(name)` は引数が名前だけ**(engine.js:653)。呼び出し元の `buildOsmItems`(engine.js:1146)は
   `isExcludedName(spot.name)` と**名前だけ**を渡しており、この時点でタグもカテゴリも見えない。
   さらに `fromOsmSpot()` は `spot.tags` を item に載せない。
   **`isExcludedName` に書こうとすると必ず行き詰まる。**
   → 正しい置き場所は `merged` 配列に対する**後段フィルタ**(R127 と同じ場所)。
2. **統合(dedupe)より後に置くこと**。`NAME_PROTECT_SUFFIX` には `動物園`・`水族館` が入っており、
   これは wiki 記事側の保護。統合前に落とすと、R127 のコメントにある松山城と同じ形で
   **OSM 側が持つ公式サイトごと消える**可能性がある。実測では8件とも website 無しなので今回の実害は無いが、
   **R127 と同じ後段に置けば構造的に起きない**ので、そこに置くこと。

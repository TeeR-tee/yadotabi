## 目的

R158 の残った副作用「展開後のカードの番号が飛ぶ(6, 9, 10, 17, 19, 21…)」への回答。
前サイクルは「地図のピンとの一致を優先した意図的な仕様」としたが、**計画役が実測したところ、6番以降のピンは地図に存在しない**。番号が指す先が無いので、飛び番号は「一致」を守っているのではなく、**何も指していない番号を飛び飛びに見せているだけ**だった。

## ★実測で判明した前提(計画役が5エリアで実測・ファイル変更0回・外部API0回)

`?fixture=<area>` を390幅で開き「もっと見る」展開後の DOM を計測した(Playwright)。

### (A) 6番以降のピンは**存在しない** — 展開してもピンは5個のまま

| エリア | 展開前ピン | 展開前カード | **展開後ピン** | 展開後カード |
|---|---|---|---|---|
| 草津 | 5 | 5 | **5** | 25 |

| 道後 | 5 | 5 | **5** | 28 |

原因は `renderFeedMap()`(`app.js:1495`)が `state.cards.forEach`(=初期5件)しか回さないこと。`state.more` は地図を一切見ていない。

### (B) フッターの表記は実在する

5エリアすべてで `.morenote` = **「6番以降は地図に表示していません。」**(`app.js:1136` の `moreHtml()` が `startNo = state.cards.length + 1` で生成)。**アプリ自身が「6番以降に地図の対応は無い」と明言している。**

### (C) ★6番以降の番号バッジは**押しても何も起きない死んだボタン**

`app.js:2116` のクリック処理は `state.cards[Number(article.dataset.index)]` を引く。`state.cards` は5件なので `index >= 5` は **`undefined`** になり、`if (badgeCard && feedMap)` が偽で**何もせずに return する**。実測(バッジをクリック→300ms後の `.pin--flash` 数):

| エリア | 押したバッジ | `.pin--flash` |
|---|---|---|
| 草津 | 9番 | **0** |
| 箱根 | 18番 | **0** |
| 道後 | 10番 | **0** |
| 別府 | 10番 | **0** |
| 城崎 | 20番 | **0** |

つまり 6番以降のバッジは、**`aria-label="18番のピンを地図で光らせる"` と名乗りながら、光らせるピンが無く、押しても地図が動かない**。飛び番号以前に、**嘘のラベルを持つ死んだボタンが1画面に17〜23個**ある(やどたびの「推測を書かない・嘘を書かない」方針に正面から反する)。

### (E) 各案の見た目(スクリーンショットで実測・DOM を書き換えて比較)

- **案A(現状)**: 道後で「宝厳寺(番号なしの束末尾)」の次に **⑨松山城**。6→9 の飛びは目に付くが破綻はしていない。**ただし押しても何も起きない**((C))。
- **案B(6番以降のバッジを消す)**: バッジを `remove()` して撮影。写真ありカードは**写真の左上が空くだけで違和感ゼロ**。初期5件との差(バッジの有無)が「地図に載っているのは上の5件」という区別として読める。
- **案C(束内で1から連番)**: 番号を振り直して撮影 → **6件目の松山城が「①」になり、地図のピン①(伊佐爾波神社)と番号が衝突**。同じ画面に「1」が2つ出て、しかも別の場所を指す。**実測して最悪だと分かった**。
- **案D(全ピンを地図に出す)**: 地図コンテナは **390 × 220px = 85,800px²**(モバイル実測)。ピンは 24×24 で `nudgeOverlaps` の最小間隔は `SUB_DIST = 26px`。**25個を26px間隔で置くには最低でも 25×26² ≒ 16,900px² の「重ならない配置」が必要だが、実際のスポットは宿の周囲数kmに偏在**しており、実測した5個ですら `nudgeOverlaps` でずらしている。25個では地図の実像(道路・地形)が番号で埋まり、**初期5件の「上位はここ」という意味も消える**。

### (F) `feedcard--bare` の存在(★案Bの罠)

写真も要約も営業時間も公式サイトも無いカードは `feedcard--bare` になり、**バッジが `.feedcard__media` ではなく `.feedcard__body` の先頭にインラインで置かれる**(`app.js:1032`、`style.css:443`)。展開後の bare カード数(**全て index>=5**): 草津6 / 箱根9 / 道後11 / 別府8 / 城崎8。ここでバッジを消すと `.feedcard__body` の先頭要素が変わるので、**`feedcard--bare` 側は「バッジを消す」だけで済む**(`(isBare ? noBtn : '')` を空文字にする)ことを確認すること。

## 推奨: **案B(6番以降は番号バッジを出さない)**

理由は3つ。①**番号が何も指していない**((A)(B))。②**押しても何も起きない死んだボタンで、aria-label が嘘**((C))。③消しても**見た目が破綻しない**((E)案B)。案Cは番号衝突で即却下、案Dは地図が埋まって初期5件の意味が消える。

## 実装方針

1. `cardHtml(card, index)` に**第3引数 `withNo`** を足す(既定は `true`。**既存の `state.cards.map(cardHtml)` は `map` が第2引数に添字・第3引数に配列を渡すため、配列が truthy 評価されて `withNo=true` になる** — それでも意図を明示するため `state.cards.map(function (c, i) { return cardHtml(c, i, true); })` と書き換える)。
2. `withNo` が偽のとき **`noBtn` を空文字にする**。`data-index` は**今のまま残す**(`observeCards()` / passive log / `state.cards[dataset.index]` が使う)。`.feedcard__media` の箱・`feedcard--bare` の判定・`aria-label` の文言・`.feedcard__no` の CSS は**1行も触らない**。
3. `moreBundledHtml()`(`app.js:1219` 付近)の2か所の `cardHtml(...)` 呼び出し(束分け成功時と失敗時のフォールバック)を **`cardHtml(rest[i], i + offset, false)`** にする。**ここが唯一の挙動変更点。**
4. **`.morenote` の文言は変えない**。「6番以降は地図に表示していません」は依然として正しく、かつ「だから番号が無い」の説明になる。
5. CSS は**追加も変更もしない**(バッジを出さないだけなので新しい見た目は生まれない)。

## 実装上の罠

1. **`flashPin()` と `feedSpotMarkers` に触らない。** `feedSpotMarkers` は `state.cards` と同じ順(`app.js:132`)で、1〜5番は今まで通り動く。**`check-pinflash.mjs` は 1/2/3番しか押さないので無改変で通るはず**(通らなければ実装が1〜5番を壊している)。
2. **`data-index` は消さない。** `observeCards()`(`app.js:1302`)が `.feedcard[data-index]` を拾い、`app.js:2092` の `state.cards[Number(art.dataset.index)]` も見ている。**消すのはバッジだけ。**
3. `cardHtml` を `.map(cardHtml)` のまま渡すと第3引数に**配列**が入る(truthy なので偶然動くが)。**明示的に `true` を渡す形に書き換える**こと。
4. **`feedcard--bare`** は展開後に 6〜11枚ある((F))。`(isBare ? noBtn : '')` の側も空にしないとバッジが残る。**5エリアで `.feedcard--bare .feedcard__no` が0個であることを実測すること。**
5. `check-more.mjs:91` は `.feedcard` の6枚目のバッジが `'6'` であることを assert している。**このまま実装すると必ず赤くなる**。「6枚目に `.feedcard__no` が**存在しない**」へ反転させる(消すのではなく反転)。
6. `check-bundle.mjs:121` は全カードの `.feedcard__no` を読んで「1..N を欠落・重複なく1回ずつ」を検査している(R158 で入れた)。**「初期5件だけが1..5を持ち、6件目以降は `no === null`」**に改める。**検査を消さずに条件を書き換える**こと。
7. `check-a11y.mjs:25` は `.feedcard__no` のタップ領域44pxを見る。**初期5件が残るので対象は消えない**(0件になって「検査対象なし」で素通りしていないか、出力の件数を必ず確認する)。
8. `check-keyboard.mjs:134` は `data-no="1"` を focus して Enter。**1番は残るので無改変で通る。**

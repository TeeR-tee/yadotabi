## 実装方針

**`make-fixture.mjs` の wiki 取得を `geo.js` と同じ同心円方式に揃え、5エリアを取り直す。** rank には一切触らない。

1. `make-fixture.mjs` に `WIKI_NEARBY_RING_RADII_M = [3000, 6000, 10000]` を足し、`baseParams(r)` を半径引数付きにする(`geo.js:923-939` と同じ形)。
2. 半径ごとに `continue` を最大3回追い、`pages` を **pageid キーで上書きマージ**する(`geo.js:945-951` と同一。重複排除がそのまま効く)。
3. **リクエスト間に1秒スリープ**を入れる(既存の Overpass 側と同じマナー。最大 3半径 × 4回 = 12回/エリア)。
4. 5エリアを `node scripts/make-fixture.mjs <area>` で**1回ずつ**再生成し、`wiki` が50件超になったことを確認する。
5. `slim-fixtures.mjs` の keep-list は既存のまま(OSM 側は変えない)。

**期待値(計画役の試算)**: `img+sum` が付くと base が **+40点**。大涌谷 `−25.6→+14.4`、彫刻の森 `+1.1→+41.1`、箱根関所 `−19.4→+20.6`、箱根神社 `−16.2→+23.8`。現 cards 5位(石垣山)が `48.8`、more 最下位(弥坂湯)が `−3.7` なので、**主要スポットは more 圏内〜cards 下位まで浮上する**見込み。**ただし (D) の減点が乗るので「必ず初期5件に入る」とは約束しない**(完了条件を参照)。

## 却下した案とその理由

- **rank の重みを変える(距離減衰を弱める / 知名度加点を足す)** … **制約で変更禁止**。かつ症状は重みではなく**入力データの欠落**なので、重みを触ると欠落を隠すだけで他エリアが壊れる。
- **`CATEGORY_PENALTY` の母数を cards に限る** … 筋は良い((D))が**閾値・重みの変更に当たり禁止**。(B) を直さないまま入れると、**効いたのがデータ補充か減点緩和かを切り分けられない**。R160 として別起票する。
- **主要スポットのホワイトリストを持つ** … 5エリアに手で名前を書くのは**やどたびの「推測を書かない」方針違反**で、エリアを増やすたび破綻する。順位を偽装しているだけで提案の質は上がらない。
- **`osmRadiusM` を広げる** … OSM は既に箱根30km・他15kmで**主要スポットは全部入っている**((A))。広げても `img/sum` は付かない。無関係。
- **中心座標を強羅・芦ノ湖寄りに動かす** … 中心は箱根湯本駅から323mで**正しい**((A))。動かすと「宿の周り」という製品の前提が壊れ、湯本側の候補が落ちる。
- **`fixtures` を手編集して wiki を足す** … 実データと乖離した固定データは**検査の意味を失わせる**。取り直しなら公式APIの正しい使い方に揃う。
- **`geo.js` を触る** … **既に正しい**。変更理由が無い。

## 実装上の罠

- **`fixtures/` は原則変更不可の例外運用**。今回は「取り直し」として**明示的に許可**されているが、**変更してよいのは5つの `.json` と `make-fixture.mjs` だけ**。
- **外部APIを叩く作業**。`make-fixture.mjs` は Wikipedia と Overpass を実際に呼ぶ。**1エリアにつき1回まで**。失敗しても連打しない(Wikimedia は UA 無し/高頻度を429で弾く)。Overpass が混むので**エリア間も数十秒あける**。
- `User-Agent` ヘッダを**必ず残す**(`make-fixture.mjs:158-160`)。消すと429。
- `pages` のマージは `Object.assign({}, prev, page)` の**順序を守る**。逆にすると `continue` で後から来た `extract` が古い空値で上書きされる。
- fixture が肥大するので**サイズを確認**する。極端に増えたら `slim-fixtures.mjs` を通す。
- **`generatedAt` が変わるので全fixtureに差分が出る**のは正常。
- **`check-nosummary.mjs` に注意**: 要約の無いカードの見え方を検査している。wiki が増えて「要約なしカード」が消えると**この検査の前提が崩れて落ちうる**。落ちたら**検査の期待値を実態に合わせて直す**(検査を消さない)。
- `check-firstcard.mjs` / `check-more.mjs` / `check-reason.mjs` / `check-r5.mjs` も**具体的な件数や名前を持っている可能性**がある。落ちたら**実態が正しいことを確認してから期待値を更新**する。

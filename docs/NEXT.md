徒歩分数もGoogleマップ経路リンクも意味をなさない。実測で上位30枚に3件残っているのでこれを落とす。

## 実装方針

既存の**定義文の述部判定**(`definitionPredicate()` engine.js:708、`definitionScope()` engine.js:691)の
枠組みにそのまま乗せる。R119〜R121 と同じ形なので新しい仕組みは要らない。

1. **人物(構造で見る)**: 語の列挙ではなく**生没年の括弧**という構造で検出する。`definitionPredicate` は
   主題部を捨てるため、生没年は**述部ではなく extract の先頭(scope 側)**にある点に注意。
   `isExcludedArticle` の中で `extract.slice(0,120)` に上記の正規表現を当てる。
   語の列挙にしない理由は、外国人・古人・職業の書かれない人物を語で網羅するのは不可能で、
   「生没年が括弧で入る」構造の方が人物記事の定義として正確だから。この根拠をコメントに残すこと。
2. **出来事**: `DEFINITION_NOT_PLACE = ['戦いである', '合戦である']` のような定数を新設し、述部で見る。
   **`戦い` 単体・`合戦` 単体は絶対に入れない**(「石橋山の戦いの古戦場」「〜の戦いの舞台となった城」
   のような**地物の記事**を巻き込むため、必ず `〜である` の形で定義文の述部に限る)。
   `合戦である` は4エリアではヒット0件だが、`戦いである` と同趣旨の取りこぼし塞ぎとして置いてよい
   (0件の語で現状の判定は1件も変わらないことを確認してから足す。R121 の `刑務所` 等と同じ扱い)。
3. **球技場**: `TITLE_KEYWORD_NG` に `球技場` を1語、`EXTRACT_KEYWORD_NG` に `球技場である` を1語足す。
   R79 の並び(`競技場`, `運動場`, `武道館` の隣)に置き、R79 の取りこぼしだったとコメントに書く。
4. **保護リストとの順序**: `isProtectedName()`(engine.js:592 付近)より**前に置くか後ろに置くか**を
   実装時に実測で決める。4エリアで両方試し、`公園`/`記念碑`/`史跡`/`城` 等で保護されている候補が
   1件も巻き込まれない方を採り、**選んだ理由を NIGHTLOG に1行残す**。
   (参考: 今回の3件はいずれも保護語で終わる名前ではないので、どちらでも落ちるはず。
    安全側=保護より後ろ、を既定とし、それで3件落ちるなら余計な前倒しはしない。)
